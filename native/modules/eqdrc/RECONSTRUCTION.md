## 参数文件格式

已观察的写入结果固定为 360 字节，无额外文件头或校验；数值是小端 32 位整数 / IEEE-754 binary32。以下偏移与头文件、逐字段修改实验相符：

| --- | ---: | ---: | --- |

每个滤波器：开关 +0、类型 +1、填充 +2/+3、采样率 +4、Q +8、增益 +12、频率 +16。每个 DRC 点依次是 X/Y/W 三个 float。填充字节也原样写出，不能在兼容接口中默认为全部为零。新结构用显式 `reserved` 成员保存这些字节，编码器不直接把宿主结构体内存写进文件。

136 组数据包含默认值、100 个字段的逐项修改、23 个填充字节、4 种常量填充及8 组确定性的伪随机字节。写入返回码、文件全部字节、读回的全部字节及输入不变性均与原 DLL 比较。伪随机字节包含不合法的 DSP 参数，仅用于确定文件搬运语义，不送入 DSP 函数。

### 原 DLL 的非对称文件读写

原 DLL 写出原始二进制数据，但读入表现为 Windows CRT 文本模式：

- `0D 0A`（CRLF）读成 `0A`。
- `1A`（CTRL-Z）结束读取。
- 单独的 `0D` 保留。
- 空文件、短文件仍返回 0；未覆盖的输出字节保留调用方原值。
- 最多读取 360 个转换后的字节，之后的数据忽略。

例如文件 `01 0D 0A 02 1A 03` 只覆盖目标开头的 `01 0A 02`，其余部分不变。因此旧 DLL 自身并不保证任意二进制参数的写入/读回恒等。这是必须用原 DLL 输出作为断言的原因。

C 兼容层在所有平台用二进制流显式模拟上述转换；不使用宿主的文本模式，以免在 POSIX 上悄悄改变行为。严格编码/解码则要求长度恰好 360，不做文本转换，参数错误时输出不变。

已验证错误：空路径 -1、空目标 -2（两者均空时优先 -1）、无法打开写入路径 -3、无法打开读取路径 -4。磁盘写满、底层流故障、Unicode 文件名、特殊设备路径尚未做原 DLL 对照；新实现检查 I/O 错误并返回 -3/-4，不声明这些情况与原库缺陷逐项一致。

## 坐标转换

有效 UI 参数指维度 > 1、有限且递增的范围；EQ 频率须为正。范围外的正常有限输入会外推，不裁剪。空指针、NaN、无穷、退化范围及 int 溢出不在当前兼容契约中。

- EQ x 轴按 `log10` 插值，分母 `xNum - 1`；y 轴线性插值，分母 `yNum - 1`。
- `EqCalcXToFreq` 先计算对数步长再乘 x，且会把零 startFreq 改为 1e-6；包装层的零起始频率及精确横坐标测试补充验证了这两个行为。
- EQ 的两个反向接口使用向零截断转换到 int。
- DRC 坐标到 dB 使用 `WidthX - 1` / `HeightY - 1`。
- DRC dB 到坐标使用完整 `WidthX` / `HeightY` 并取最近整数。这两个方向不是严格互逆，右端点反向映射到 WidthX。
- 整数返回必须完全一致；EQ 浮点误差不超过 `1e-10 * max(1, abs(reference))`，DRC binary32 绝对误差不超过 `2e-5 dB`。

## EQ 完整曲线

`src/eq.c` 按原库路径实现：

1. 校验全部 10 个滤波器，包括关闭的滤波器；EQ 总开关关闭时也先校验，成功后不修改输出。
2. 生成低通、高通、峰值、低架或高架的 binary32 系数。角频率常量是 `6.2831854820251465`（float 的 2π 提升到 double）；三角函数、架式公式与归一化过程中的 float 舍入位置均保留。类型 5 返回 -6。
3. 把开启滤波器级联，按 double 运算生成 4096 点冲激响应。
4. 做 4096 点实数 FFT，只用前 2048 个频率点；频率坐标间隔为 `(第一个滤波器采样率 / 2) / 2047`，即使第一个滤波器关闭也如此。
5. 频谱幅度转 dB，对绘图的对数频率轴做四点 Lagrange 插值。第一个最近点依据 `abs((int)(binHz - queryHz))` 选择，后续选择邻点。插值项逐个累加到调用方的 Y 数组，不清零也不裁剪。

`startFreq == 0` 被改成 `1e-6`，这个 UI 结构修改也纳入断言。原库在零频谱附近可能产生 Inf/NaN；兼容实现保留分类，渲染层的修复属于另外的职责。

FFT 使用固定版本的开源 CMSIS-DSP v1.14.4 子集，位于 `native/third_party/cmsis-dsp/`，含 Apache-2.0 许可证、上游提交及文件 SHA-256。生成器只保留所需的正向变换和表，将 uint64 表位模式转为等值 double 常量，去除指针别名风险。普通构建无需联网。这里没有从 DLL 提取并分发机器码或私有数据表。

曲线用例包含两种采样率、5 种滤波器、Q/增益/频率边界、24 组确定性多级级联、2/1024 点图、零起始频率、非零输出累加、关闭状态、混合采样率、Nyquist 边界、参数及 UI 错误。FFT 算法和运算顺序影响约 -300 dB 深衰减处的结果，不能用另一种 FFT 加上大容差掩盖偏差。

## DRC 完整曲线

`src/drc.c` 保留以下实测行为：

- 开启时 SegNum 必须为 2–6，首末 X 必须为 -100/0，X 可以相等；内部 Y 允许大于 0，末端 Y 不允许。Type 错误返回 -14，RmsTime 错误返回 -10。错误优先级按对照用例验证。
- 绘图参数副本强制 `At=0`、`Rt=0`、`Type=0`，再修正 X 与 W；W 按相邻 X 间距限制，不简单限制到 20。修改后的完整 112 字节结构与原库比较。
- 开关关闭并不直接返回一条旁路直线：它跳过部分参数校验，后续仍走曲线计算及参数修正。
- 将输入 dB 经 `powf` 转为线性幅度，再通过 float 检测、分段线性/二次过渡、带舍入偏置的增益平滑及原库的指数近似转换回 dB。直接画几段直线无法得到相同结果。
- 零 Attack/Release 仍保留增益平滑中的 `0.5` 系数和 `+2` 偏置。dB→线性指数保留原库的 `236` 比例近似，不替换为 `ln(10)/20`。
- 输出覆盖调用方数组，首点小于 -100 时裁到 -100；其余点不按图的 y 范围裁剪。
- `DrcDrawGet` 从 `struDrcPrm2.ModifiedDrcPrm` 复制完整结构；空对象 -2，空输出 -3。

用例覆盖 2–6 段、两种采样率、W=0/0.01/6/20/100、重复 X、负 W、正的内部 Y、不同时间与检测模式、关闭状态及参数修正、局部 UI 范围、511/512/513/1024 点图和错误优先级。每个曲线/修正结构缓冲区都有前后哨兵检查。

## 明确的安全差异与后续工作

不复现原 DLL 的崩溃或未定义内存访问。C 实现为 `DrcDraw` 的空参数/空修改结果返回 -3；启用 EQ 且 `xNum=1` 返回 -12；NaN/Inf 参数被拒绝。这些用例由 C 测试验证，不把危险调用混入原 DLL 的共享采集批次。正常调用方仍须分配至少 xNum 个 double 或 WidthX 个 float，旧 ABI 没有缓冲区容量参数。

`eqdrawDLL` 点数组包装层和 `SoundEffect.dll` 音频处理已分别在相邻 `eqdraw`、`soundeffect` 模块实现并验证。后续重点是应用后端切换，以及在 macOS/Linux/ARM64 上编译和验证。本模块仍只负责公开曲线/文件 API，音频兼容范围见 soundeffect 模块记录。

## 验证

`npm run native:compare` 在 Windows x64 / MSVC Release 运行：2 个 C 测试与 6 组 Node 差分测试通过，现场原 DLL 输出与保存基准一致。441 组曲线的 37,361 个输出元素中，12 个非有限分类一致，有限值实测最大差异为 0 dB。回归阈值为 EQ 绝对误差 1e-8 dB、DRC 2e-5 dB；整数、返回码、修改结构及输入副作用精确比较。

这些结论针对已列出的用例，不证明任意输入和平台上的逐位相同。当前没有在 macOS/Linux/ARM64 运行验证，也尚未切换 Electron 的运行时后端。
